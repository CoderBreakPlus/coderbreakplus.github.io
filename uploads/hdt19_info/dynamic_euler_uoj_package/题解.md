# 动态维护欧拉回路：半边配对、FHQ Treap 与异或采样

本文对应简化后的 C 数组版 `std.cpp`：一条原图边对应一个 Treap 结点，使用常规 `split/merge` 维护路径；使用异或采样寻找不同回路的公共顶点，采样失败时精确扫描。固定上限的数据使用 C 数组，变长邻接表与接口返回值使用 `vector`，原图边的查找使用 `map`。

全文采用当前限制 $n,q\le 2\times10^5$。代码的采样参数为 `groups=3,levels=20`。

**这份实现的答案正确性不依赖采样成功。文末的 $O(N\log^3N)$ 是带明确假设的复杂度分析，尚不能作为当前实现对任意操作序列的已证上界。** 其中 $N=\max(n,q,2)$。

## 1. 整体思路：先维护若干条边不重的路径

每次加删边之后，图可能不连通，也可能有奇度点。这时不必强行维护一条欧拉回路，而是把所有边划分成若干条路径与回路。

这里的“路径”允许经过同一个顶点多次，但每条边只能出现一次，即图论中的迹。不同路径之间也不能共用边。

我们希望做到：

1. 每条原图边恰好属于一条维护中的路径或回路。
2. 每个顶点至多有一个未接上的路径端点。
3. 每条路径或回路的边序列用一棵 FHQ Treap 维护。

查询保证所有点的度数都是正偶数。由第二条性质可知，此时每个点都没有未接上的端点，所以维护中的所有路径都已经闭合成回路。

原图连通，因此只要还有多条回路，就能找到两条经过同一个顶点的回路，将它们拼起来。反复执行，最终就得到覆盖全部边的一条欧拉回路。

需要分别解决的事情是：

- 加删边时，怎样局部调整路径；
- 怎样维护路径方向与哈希；
- 查询时，怎样快速找到两条有公共顶点的回路。

## 2. 半边与配对：把“沿哪条边继续走”记录下来

### 2.1 一条边对应两个半边

给每次加入的边分配一个新编号 $e$。其两个半边编号为

$$
p=2e,\qquad p\oplus1=2e+1.
$$

半边表示“某条边在某个端点处的那个端口”。它既确定一条边，也确定这条边的一个端点。

例如边 $e=(u,v)$：

- `ver[2e]=u`；
- `ver[2e+1]=v`；
- `p>>1` 得到半边 $p$ 所属的边；
- `p^1` 得到同一条边的另一个半边。

选择半边 $p$ 作为出发端，就表示沿这条边从 `ver[p]` 走向 `ver[p^1]`。

半边编号固定；路径的行走方向可以改变。同一条边反向行走时，只是把出发半边由 $p$ 换成 $p\oplus1$。

### 2.2 同一个顶点处的半边两两配对

若 `mate[p]=q`，表示半边 $p,q$ 在同一个顶点处接起来。必须满足

$$
\operatorname{ver}[p]=\operatorname{ver}[q],\qquad
\operatorname{mate}[p]=q,\qquad
\operatorname{mate}[q]=p.
$$

从半边 $p$ 出发，先沿原图边走到 $p\oplus1$，然后通过配对选择下一条边，因此下一步的出发半边是

$$
p\leftarrow \operatorname{mate}[p\oplus1].
$$

`mate[p]=0` 表示这个半边尚未配对，是一条开放路径的端点。

可以把所有半边看成一个辅助结构：每个半边总是和自己的对侧半边相连，还可能和 `mate` 相连。这样每个半边的度数至多为 $2$，整个结构自然分解成路径与环。沿原图边连接和配对连接交替行走，就得到原图中的路径与回路。

### 2.3 每个顶点至多留下一个未配对半边

`unmatched[v]` 记录顶点 $v$ 当前唯一的未配对半边，若不存在则为 $0$。

当半边 $p$ 需要重新配对时，调用 `expose(p)`：

~~~cpp
void expose(int p){
	if(!p)return;
	int v=ver[p],q=unmatched[v];
	if(q){unmatched[v]=0;join(p,q);}
	else unmatched[v]=p;
}
~~~

如果 $v$ 已经有一个未配对半边 $q$，就将 $p,q$ 接起来；否则暂存 $p$。

在每次外部操作完成后，每个顶点至多有一个未配对半边。因为每次配对消耗两个半边，未配对半边的数量与该点度数奇偶性一致。于是：

- 奇度点恰好有一个未配对半边；
- 偶度点没有未配对半边；
- 查询时所有维护中的路径都闭合。

在一次加删边操作的中间步骤，可以短暂出现两个待配对端点；`expose` 会将它们处理完。

## 3. FHQ Treap：一条边一个结点

### 3.1 为什么维护边序列

顶点可以在欧拉回路中重复出现，而每条边只出现一次。以边作为 Treap 结点，既方便直接定位要删除的边，也能用一个布尔翻转标记改变整段路径的方向。

结点编号就是边编号 $e$。每棵 Treap 的中序序列表示一条路径的边序列。

主要字段如下：

| 字段 | 含义 |
|---|---|
| `l,r,fa` | 左儿子、右儿子、父亲 |
| `sz` | 子树包含的边数 |
| `p` | 当前这条边沿维护方向行走时的出发半边 |
| `first` | 子树表示的整段路径的出发半边 |
| `last` | 整段路径最终到达的半边 |
| `h,rh` | 正向、反向行走时的哈希 |
| `pri` | FHQ Treap 的随机优先级 |
| `rev` | 整段路径尚待向儿子下传的翻转标记 |

如果中序出发半边序列为 $(a_1,\ldots,a_k)$，那么

$$
\operatorname{first}=a_1,\qquad
\operatorname{last}=a_k\oplus1.
$$

注意 `last` 是最后一条边的到达半边，不是最后一条边的出发半边。

回路也用线性序列存储，只是在序列两端额外满足

$$
\operatorname{mate}[\operatorname{first}]
=\operatorname{last}.
$$

因此，切开一条回路的表示方式，只是选择一个序列起点，不是真的删除原图中的连接。

### 3.2 正反向哈希

设整段路径经过的顶点为

$$
s_0,s_1,\ldots,s_k,
$$

其中共有 $k$ 条边。取 $B=100$、$P=998244353$，在 Treap 中维护

$$
h=\sum_{i=0}^{k-1}s_iB^i\bmod P,
$$

即只记录每条边的起点，暂时不放入最后一个顶点 $s_k$。

反向行走时，依次经过 $s_k,s_{k-1},\ldots,s_0$，因此维护

$$
rh=\sum_{i=0}^{k-1}s_{k-i}B^i\bmod P.
$$

**反向哈希不是简单地把原来的 $k$ 个起点倒序。** 反向行走时，每条边的新起点是它原来的终点。

记左右子树为 $\ell,r$，边数分别为 $L,R$，当前边的出发半边为 $p$，则

$$
h_x=h_\ell+\operatorname{ver}[p]B^L+h_rB^{L+1}\pmod P,
$$

$$
rh_x=rh_r+\operatorname{ver}[p\oplus1]B^R+rh_\ell B^{R+1}\pmod P.
$$

预处理 `pw[i]=100^i mod P`，就能直接维护。

最终查询时，补上最后一个顶点：

$$
\operatorname{answer}
=h_{\mathrm{root}}
+\operatorname{ver}[\operatorname{last}_{\mathrm{root}}]
 B^{\operatorname{sz}_{\mathrm{root}}}
\pmod P.
$$

下文始终以 $m$ 表示当前原图边数，完整答案是 $s_0,\ldots,s_m$ 的哈希，重复出现的末尾起点也要计入。

### 3.3 整条路径反向

如果原来的出发半边序列是

$$
(a_1,a_2,\ldots,a_k),
$$

反向后应该变成

$$
(a_k\oplus1,\ldots,a_2\oplus1,a_1\oplus1).
$$

既要反转边序列，也要反转每条边的行走方向：

~~~cpp
void reverse(int x){
	if(!x)return;
	swap(t[x].l,t[x].r);
	swap(t[x].first,t[x].last);
	swap(t[x].h,t[x].rh);
	t[x].p^=1;
	t[x].rev^=1;
}
~~~

当前结点的方向立即反转，儿子内部的反转留给 `rev` 下传。

`first,last` 只交换，不异或 $1$。原来的到达半边成为新的出发半边，仍然是原来的那个端口。

原有的 `mate` 不需要修改。配对是无向且对称的，沿反方向仍然可以通过同一组配对行走。

### 3.4 分裂、合并和定位

采用通常的隐式 FHQ Treap 操作：

- `split(x,k,a,b)`：前 $k$ 条边归 $a$，其余归 $b$；
- `merge(a,b)`：将 $b$ 的边序列接到 $a$ 后面。

每次下探前调用 `push`，回溯时调用 `pull`。`pull` 还负责设置两个儿子的 `fa`。每次分裂、合并产生的树根，其 `fa` 必须为 $0$。

通过父指针有两个辅助函数：

- `getroot(x)`：不断向父亲走，找到路径所属的 Treap 根；
- `getrank(x)`：求边结点 $x$ 的中序排名。

求排名之前，需要用 `push_path(x)` 从根到 $x$ 下传翻转标记。否则，“当前结点是左儿子还是右儿子”的判断可能还没有反映真实方向。

`getroot` 只关心树的包含关系，不关心左右顺序，因此不必下传翻转标记。

### 3.5 维护当前所有路径的根

用 C 数组 `roots` 和计数器 `root_count` 存放当前所有 Treap 根，`where[x]` 记录根 $x$ 在数组中的位置。

删除一个根时，用数组最后一个根填补空位，因此插入、删除都只需 $O(1)$。

在拼接、切分、旋转路径前，先将旧根移出根列表；操作完成后，再将新根加入。这样根列表始终对应当前的完整路径集合。

## 4. 连接两个裸露端点：join

`join(p,q)` 的调用前提是：

- $p,q$ 位于同一个原图顶点；
- 两个半边当前都未配对。

设它们所在的 Treap 根分别为 $x,y$。

若 $x=y$，这两个端点属于同一条开放路径。直接设置

~~~cpp
mate[p]=q;mate[q]=p;
~~~

就将它闭合成回路，不需要改变 Treap 的边序列。

若 $x\ne y$，要让第一条路径从别处走到 $p$，再从 $q$ 出发走过第二条路径。于是：

~~~cpp
if(t[x].last!=p)reverse(x);
if(t[y].first!=q)reverse(y);
insert_root(merge(x,y));
~~~

为什么只翻转就够？

因为未配对半边一定是开放路径的端点。若 $p$ 不是第一条路径的末尾，就一定是开头；翻转后便成为末尾。$q$ 同理。这里不需要把路径内部的某个位置移动到端点。

例如两条路径当前存成

$$
(C,B,A),\qquad(E,D,C),
$$

其中 $p,q$ 分别是两条路径在 $C$ 处的半边。翻转后得到

$$
(A,B,C),\qquad(C,D,E),
$$

配对并合并后就是

$$
(A,B,C,D,E).
$$

$p,q$ 是同一个顶点上的两个不同半边，而 Treap 存储的是边，所以不会因为两段路径都有顶点 $C$ 而重复一条边。

## 5. 加边与删边

### 5.1 加边 add(u,v)

加入新边时，先把它视为一条只有一条边的开放路径：

1. 分配新边编号 $e$，对应半边 $2e,2e+1$。
2. 设置两个端点，在 `edge_id` 中记录这条边。
3. 生成这两个半边的采样信息，更新邻接表与辅助统计。
4. 初始化并加入这棵单结点 Treap。
5. 分别调用 `expose(2e)`、`expose(2e+1)`。

两个端点会分别与原来留下的端点连接。最终可能合并两条路径，也可能闭合成回路，`join` 会统一处理。

边删除后再加入时使用新编号，旧编号不复用。总共加入的边数不超过操作数 $q$，所以按 $q$ 分配边结点就够了。

### 5.2 删边先考虑序列怎样变化

设要删除的边在其所属 Treap 中表示为

$$
A,\ e,\ B.
$$

通过两次普通 `split`，可以分离出 $A$、单独的 $e$、$B$。

如果原来是开放路径，删边后得到两条路径 $A$ 和 $B$，分别放回根列表，空路径忽略。

如果原来是回路，线性表示的末尾与开头本来还接着。删去 $e$ 后，剩下的是一条开放路径，顺序应当是

$$
B+A.
$$

原因是：从 $e$ 后面开始，先走完 $B$，再经过原来回路的首尾连接走完 $A$。因此代码是

~~~cpp
if(closed)insert_root(merge(right,left));
else{insert_root(left);insert_root(right);}
~~~

判断原路径是否闭合，可以检查

~~~cpp
bool closed=mate[t[r].first]==t[r].last;
~~~

### 5.3 恢复顶点处的配对

设被删边的两个半边为 $p,p\oplus1$，原来的配对半边为

$$
a=\operatorname{mate}[p],\qquad
b=\operatorname{mate}[p\oplus1].
$$

先保存 $a,b$，再删除结点并解除这两组配对。

对 $p$ 所在顶点，有两种情况：

- $a\ne0$：原来 $p$ 与 $a$ 配对，现在 $a$ 变成裸露端点；
- $a=0$：原来 $p$ 本身就是该顶点记录在 `unmatched` 中的端点，现在这个端点随边一起删除，应清空对应记录。

另一个端点同理。然后调用

~~~cpp
expose(a);expose(b);
~~~

即可重新保证每个顶点至多剩一个未配对半边。

例如某个顶点原来是奇度点，已有裸露半边 $z$。如果被删除的半边 $p$ 原来与 $a$ 配对，删除后就留下 $a,z$ 两个裸露半边，`expose(a)` 会将它们配起来。这个顶点删除一条边后度数变偶数，恰好不再留下裸露半边。

### 5.4 删边时的实际顺序

当前代码依次执行：

1. 从 `map` 找到边结点，保存它两端原来的配对信息。
2. 判断是否闭合，取出旧根，切掉边结点，放回剩余路径。
3. 清除相关 `mate` 和 `unmatched`。
4. 将两个半边从邻接表及辅助采样信息中删除。
5. 对新露出的半边调用 `expose`。
6. 将被删半边的 `ver` 置为 $0$，表示它们已经失效。

辅助采样信息的删除必须在边结点已经离开有效 Treap 之后处理；其具体原因见第 8 节。

## 6. 查询的关键：找不同回路的公共顶点

查询时所有路径都已经闭合，但可能有很多条回路。

如果找到两个属于不同 Treap、且位于同一个原图顶点的半边 $p,q$，就能把对应回路拼起来。直接枚举一整条回路经过的顶点当然正确，但每次都这样做可能很慢。

为此，我们建立一个只用于寻找公共顶点的辅助图。

### 6.1 辅助图的点是原图的边

每条原图边 $e$ 对应一个辅助图顶点，也就是同编号的 Treap 结点。

对每个原图顶点 $v$，从它的邻接半边中任选一个代表半边

$$
h_v=\operatorname{representative}(v).
$$

代码直接取 `adj[v][0]`。当 $v$ 没有关联边时，代表为 $0$。

对 $v$ 的每个半边 $p$，在辅助图中连接

$$
p\mathbin{>>}1
\quad\text{与}\quad
h_v\mathbin{>>}1,
$$

并将这条辅助边的标签设为半边编号 $p$。

这样，同一个原图顶点关联的所有原图边，在辅助图中形成一颗星。

当 $p=h_v$ 时，两端是同一个辅助图顶点。这条自环对后面的异或统计贡献为零，可以在概念上忽略；实现中让同一个标签异或两次即可。

### 6.2 为什么这张辅助图够用

同一个原图顶点上的任意两条边，本来都可以通过这个顶点接起来。把它们之间的所有连接替换为一颗星，仍然保留了连通性。

因此，原图在去掉孤立点后连通，就意味着这张以原图边为点的辅助图连通。

设一棵 Treap 包含的边结点集合为 $S$。只要还有其他 Treap，$S$ 就是辅助图顶点的非空真子集，辅助图一定有边跨越 $S$ 与其补集。

找到这种辅助边的标签 $p$ 后，令

$$
q=h_{\operatorname{ver}[p]}.
$$

半边 $p,q$ 位于同一个原图顶点，所属 Treap 又不同，正好可以用来拼接回路。

辅助星形图与 `mate` 的作用不同：

- `mate` 决定当前路径实际怎样走；
- 辅助星形图只用来寻找能够把不同回路接起来的位置。

### 6.3 用异或消去集合内部的辅助边

先忽略采样。对每条标签为 $p$ 的辅助边，在它两端的辅助图顶点上都异或一次 $p$。

把 $S$ 内所有顶点的统计量异或起来：

- 两端都在 $S$ 中：标签出现两次，抵消；
- 两端都在外面：不出现；
- 恰好一端在 $S$ 中：标签出现一次。

于是得到的就是辅助图割边标签的异或和。

如果割边只有一条，这个异或和就是它的标签，可以直接恢复连接位置。割边有多条时，异或结果一般不能直接解释为某条真实割边，因此还需要采样。

## 7. 多层采样与候选验证

### 7.1 为每个半边生成固定的采样高度

设有 $R$ 组独立采样，每组 $L$ 层，层号为 $0,\ldots,L-1$。

对每个半边 $p$、每一组 $j$，在半边创建时生成一个高度 `height[p][j]`。第 $i$ 层保留标签 $p$ 当且仅当

$$
i\le \operatorname{height}[p][j].
$$

代码通过连续抛硬币生成高度，所以在有效层范围内，

$$
\Pr\bigl(\operatorname{height}[p][j]\ge i\bigr)=2^{-i}.
$$

第 $0$ 层保留所有标签，之后每上一层，保留概率减半。

同一个半边存在期间，高度固定不变。这样加入时异或一次，删除时再次异或同一份信息，就能完全撤销。

把标签 $p$ 对所有组、所有层的贡献记作一个数组 $C(p)$：

$$
C(p)_{j,i}=
\begin{cases}
p,&i\le\operatorname{height}[p][j],\\
0,&\text{否则}.
\end{cases}
$$

`toggle(s,p)` 就是执行 $s\gets s\oplus C(p)$。

对于一个与采样独立的固定割，如果它有 $k$ 条辅助割边，在保留概率 $\rho$ 的某层恰好留下一个标签的概率为

$$
k\rho(1-\rho)^{k-1}.
$$

层数覆盖当前规模时，会有一层的 $\rho$ 与 $1/k$ 同阶，因此有常数成功概率。这解释了采用几何分层的原因。动态过程的独立性问题单独放在复杂度部分讨论。

### 7.2 Treap 上维护哪些采样信息

代码中的三个数组含义如下：

| 数组 | 含义 |
|---|---|
| `value[e]` | 边结点 $e$ 自身承担的辅助边标签贡献 |
| `sum[e]` | Treap 子树中所有 `value` 的异或和 |
| `vertex_sum[v]` | 原图顶点 $v$ 的所有关联半边贡献 $\bigoplus_{p\in adj[v]}C(p)$ |

每个元素都是一个 $R\times L$ 的整数数组。

Treap 子树统计满足

$$
\operatorname{sum}[x]
=
\operatorname{sum}[\operatorname{left}(x)]
\oplus\operatorname{value}[x]
\oplus\operatorname{sum}[\operatorname{right}(x)].
$$

因此，根的 `sum` 就是整条路径在每一组、每一层上剩余的辅助割边标签异或和。

采样统计与边序列的方向、顺序都无关。`reverse` 不需要修改 `value,sum`；只更新这些统计的 `refresh(x)` 也不必下传翻转标记。

`refresh(x)` 从 $x$ 向根走，每次重新计算该结点的 `sum`。它不改变哈希与路径端点。

### 7.3 得到一个整数后必须验证

对目标根 $r$，依次尝试所有 `sum[r].a[j][i]`。设得到的整数为 $p$，只有同时满足以下条件才接受：

1. $p$ 是有效半边编号；
2. `ver[p]!=0`，它所属的原图边尚未删除；
3. $p$ 与其代表半边 $h_{\operatorname{ver}[p]}$ 属于不同的 Treap；
4. 两棵 Treap 中有一棵就是当前目标根 $r$。

对应 `crossing(p,r)`：

~~~cpp
bool crossing(int p,int r){
	if(p<2||p>2*tot+1||!ver[p])return false;
	int x=getroot(p>>1);
	int y=getroot(representative(ver[p])>>1);
	return x!=y&&(x==r||y==r);
}
~~~

异或结果有可能由多个标签组成，却碰巧等于另一条有效辅助割边的标签。只要通过上述验证，就仍然可以使用，不要求它一定来自单个被采样标签。

**程序从不把未经验证的异或结果用于拼接。** 随机采样只影响找到连接的速度，不会让错误的连接通过验证。

注意跨越目标回路时，代表半边可能位于目标回路内，也可能位于目标回路外。所以最后一项必须检查两端，不能只检查 `x==r`。

## 8. 加删半边时，怎样维护辅助星形图

代表半边变化时，概念上的星形图可能同时改变很多条辅助边。这里利用异或的可合并性，把这种变化压缩到少量结点更新。

### 8.1 邻接表与代表半边

`adj[v]` 保存当前原图顶点 $v$ 的所有关联半边，`pos[p]` 保存半边 $p$ 在邻接表中的位置。

删除 $p$ 时，把最后一个元素搬到 `pos[p]`，更新它的位置，然后 `pop_back`，所以邻接表删除是 $O(1)$。

代表始终取邻接表第一个元素。删除代表时，搬到第一个位置的半边自然成为新代表。

### 8.2 加入半边 attach(p)

设 $v=\operatorname{ver}[p]$，原代表为 $h$。若原来没有代表，就取 $h=p$。

新辅助边的两端为 $p>>1$ 与 $h>>1$，标签为 $p$，因此进行

$$
\begin{aligned}
\operatorname{vertex\_sum}[v]&\mathrel{\oplus}=C(p),\\
\operatorname{value}[p>>1]&\mathrel{\oplus}=C(p),\\
\operatorname{value}[h>>1]&\mathrel{\oplus}=C(p).
\end{aligned}
$$

随后更新代表所在 Treap 的祖先统计。新边结点在两个半边都加入之后，再统一 `pull`。

若 $h=p$，后两行作用在同一个边结点上，恰好抵消，这与自环没有贡献一致。

### 8.3 删除非代表半边

假设要删除的 $p$ 不是代表 $h$。

删边函数已经先把 $p$ 所属的边结点从有效 Treap 中取出，所以标签在被删结点一侧的贡献，已经不再进入任何有效根的统计。

剩下只需要：

1. 从 `vertex_sum[v]` 中撤销 $C(p)$；
2. 从代表结点 `value[h>>1]` 中撤销 $C(p)$；
3. 沿代表结点向上 `refresh`。

被删结点自己的 `value` 不必清理，因为这个结点以后不会复用，也不会重新加入任何 Treap。

### 8.4 删除代表半边

假设被删的 $p$ 就是旧代表。删除 $p$ 并更新邻接表以后，设新代表为 $h$，剩余半边集合为 $A$。

令

$$
T=\bigoplus_{a\in A}C(a)
=\operatorname{vertex\_sum}[v].
$$

在旧星形图中，每个剩余半边 $a$ 已经在自己的边结点上贡献了 $C(a)$；另一端的贡献在旧代表结点上。旧代表结点现在已经离开有效 Treap。

新星形图要求：这些 $C(a)$ 在各自边结点上的贡献继续保留，同时把它们的代表端贡献全部放到新代表结点上。

因此只需

~~~cpp
value[h>>1]^=vertex_sum[v];
refresh(h>>1);
~~~

就完成了整个代表切换，不必逐条处理 $A$ 中的半边。

这里 $T$ 包含 $C(h)$。新代表结点本来已有自己的那份 $C(h)$，再异或一次就抵消，正好对应新代表的自环。

若删除后邻接表为空，则没有新代表，也没有剩余贡献需要转移。

**这也是为什么删边必须先将边结点从 Treap 中切掉，再调用 `detach`：旧代表结点上的整份贡献需要先退出有效子树统计。**

## 9. 采样失败时的精确扫描

采样没有找到连接时，先尝试 `recent` 保存的最近 $64$ 个扫描结果。每个结果都重新经过 `crossing` 验证，因为对应边可能已经删除，也可能已经不再跨越目标回路。

如果缓存也没有可用结果，就精确扫描目标 Treap。

### 9.1 先标记整棵树

遍历目标根 $r$ 的全部边结点，放入 C 数组 `nodes`，并令

~~~cpp
mark[x]=stamp;
~~~

其中每次扫描递增一次 `stamp`。

必须先完成全部标记，再开始判断谁在回路之外；否则可能把尚未访问的内部结点误判为外部结点。

遍历只关心结点集合，不关心中序顺序，所以不需要下传翻转标记。

### 9.2 检查辅助星形图的两个方向

对于目标回路中的每个半边 $p$，令 $v=\operatorname{ver}[p]$、$h=h_v$。

若 $h$ 所属边结点没有被标记，说明 $p$ 在目标集合内、代表在外面，标签 $p$ 就是一条有效辅助割边。

如果 $p=h$，说明代表在目标集合内。这时枚举 `adj[v]`，寻找一个所属边结点未被标记的半边 $q$。找到后，标签 $q$ 就是一条有效辅助割边。

这两种情况覆盖了所有辅助割边：

- 普通半边在里面、代表在外面；
- 代表在里面、普通半边在外面。

由于查询时辅助图连通，目标集合又不是全部边结点，扫描必然找到一个连接。

### 9.3 扫描的代价

设目标边结点集合为 $S$，精确扫描的代价至多为

$$
O\left(
|S|+
\sum_{\substack{v:\ h_v\text{ 所属边结点}\\\text{位于 }S}}
\deg(v)
\right).
$$

每个原图顶点只有一个代表，所以它的邻接表在一次扫描中至多被完整检查一次。于是单次扫描为 $O(m)$，其中 $m$ 是当前原图边数。

**不能把这个代价直接写成 $O(|S|)$。** 即使目标回路较短，也可能包含某个高度数顶点的代表，从而检查很多外部半边。

当前代码只比较根数组最后两个根的大小，选择其中较小者作为查找目标；它没有寻找全局最小回路。找到的另一个回路，也不一定是比较大小时的另一个根。这是一项实现上的启发式选择，不构成小并大复杂度证明。

## 10. 将两条闭合回路拼成一条

找到同一顶点处的两个半边 $p,q$ 后，设其原配对为

$$
a=\operatorname{mate}[p],\qquad
b=\operatorname{mate}[q].
$$

因为查询时所有路径都闭合，$a,b$ 都存在。

### 10.1 rotate(p)：让回路从 p 出发

设 $p$ 所属边结点为 $x$，在回路 Treap 中的排名为 $k$。

先用 `getrank(x)` 下传祖先翻转标记。若当前边的出发半边不是 $p$，就反转整条回路。反转后，该边的排名变为

$$
k'=m-k+1.
$$

此时这条边的行走方向已经正确。再在它前面切开，得到前缀 $A$ 和后缀 $B$，将顺序改为 $B+A$，就让该边成为第一条边。

~~~cpp
int rotate(int p){
	int x=p>>1,r=getroot(x),k=getrank(x),a,b;
	if(t[x].p!=p){reverse(r);k=t[r].sz-k+1;}
	split(r,k-1,a,b);
	return merge(b,a);
}
~~~

回路允许循环移位。`rotate` 只改变线性表示的起点与方向，不改变任何 `mate` 配对。

### 10.2 交换两组配对

分别让第一条回路从 $p$ 出发、第二条从 $q$ 出发。

第一条线性表示的末端就是 $a$，第二条末端就是 $b$。把原来的

$$
p\leftrightarrow a,\qquad q\leftrightarrow b
$$

改成

$$
p\leftrightarrow b,\qquad q\leftrightarrow a.
$$

随后直接合并两棵 Treap：

~~~cpp
mate[p]=b;mate[b]=p;
mate[q]=a;mate[a]=q;
insert_root(merge(x,y));
~~~

行走过程变为：

1. 从 $p$ 出发，走完第一条回路，到达 $a$；
2. 经 `mate[a]=q`，继续走第二条回路，到达 $b$；
3. 经 `mate[b]=p`，回到最初的出发半边。

两条回路的边互不重复，所以拼接结果仍然边不重，并恰好覆盖两条原回路的所有边。

## 11. 两种查询

### 11.1 query()

只要 `root_count>1`，就执行：

1. 选择一个目标回路；
2. 调用 `find_crossing` 找到跨越它的辅助边；
3. 取标签半边与其代表半边；
4. 用 `splice` 合并两条回路。

每次成功拼接都使回路数减少 $1$。最终只剩一棵 Treap，其边序列就是当前图的一条欧拉回路。

返回其正向哈希，再补上最后一个顶点的贡献。

### 11.2 query_path()

从唯一根的 `first` 开始，重复输出当前出发半边所在顶点，然后转移到

~~~cpp
p=mate[p^1];
~~~

共输出 $m+1$ 个顶点。经过前 $m$ 次转移后回到起始半边，因此最后一个顶点与第一个相同。

这段遍历直接沿 `mate` 行走，不需要遍历 Treap，也不需要将全部翻转标记下传。`mate` 描述的是实际连接关系，根的 `first` 决定本次选择的起点和方向。

`query_path()` 紧跟在 `query()` 后面，中间没有修改操作，返回的序列就与上一问所维护的哈希一致。输出代价是 $O(m)$。

## 12. 正确性证明

### 12.1 半边配对始终表示一组覆盖全部边的路径

每条原图边的两个半边之间有固定连接。`mate` 只在同一个顶点处把半边两两连接，且每个半边至多有一个配对对象。

因此半边结构的每个连通块都是交替行走的路径或环，每条原图边恰好属于其中一个连通块。

`join` 只连接两个裸露端点，`del` 先解除被删边两端的配对，再连接新露出的端点；它们不会让一条边同时进入两条路径，也不会重复使用某个半边。

### 12.2 Treap 序列与半边配对表示同一组路径

单边 Treap 显然满足要求。

连接两条路径时，将端点调整到第一条末尾与第二条开头，再按同样的顺序合并 Treap，与新增的 `mate` 配对一致。

删除开放路径中的一条边，按序分为两段；删除回路中的一条边，则将后缀与前缀接起来。这恰好是解除对应配对后剩余的行走顺序。

回路旋转与整体反向不改变其边集合与连接关系。`splice` 的交叉配对又恰好对应两条旋转后序列的拼接。

所以这条不变量在所有操作后都保持成立。

### 12.3 查询时只会剩下闭合回路

每次修改完成后，每个顶点至多留下一个未配对半边。查询时每个顶点度数为偶数，其半边数量为偶数，因此未配对半边数量不可能为 $1$，只能为 $0$。

所有路径均没有裸露端点，所以全部闭合。

### 12.4 只要还有多条回路，就一定能够继续拼接

查询时原图连通且没有孤立点，辅助星形图也连通。

任取一棵并未包含全部边的 Treap，它对应辅助图顶点的非空真子集，一定存在辅助割边。

采样找到的候选经过 `crossing` 验证后才使用；若采样和缓存没有找到，精确扫描必能发现一条辅助割边。

这条割边给出了同一原图顶点处、属于不同回路的两个半边。`splice` 能将这两条回路正确拼接，且回路数减少 $1$。

因此查询最终一定得到一条覆盖全部边的回路。

### 12.5 返回路径与哈希一致

Treap 的 `h,rh` 按实际行走方向维护。唯一根的 `h` 加上末尾顶点贡献，恰好是该回路完整顶点序列的哈希。

`query_path` 从同一个 `first` 出发，沿与 Treap 一致的 `mate` 连接行走，得到的就是同一个序列。

以上正确性论证不使用任何采样成功概率假设。即使每次采样都失败，程序仍会通过精确扫描返回正确结果。

## 13. 可以直接分析的时间与空间

记 $R$ 为采样组数，$L$ 为每组层数，$N=\max(n,q,2)$。

### 13.1 常规维护的代价

一次 `pull` 或 `pull_sum` 要合并 $R\times L$ 个整数，因此是 $O(RL)$。

在通常的随机 Treap 期望高度分析适用的前提下：

- `split/merge/getrank` 等路径操作经过期望 $O(\log N)$ 个结点；
- 一次 `refresh` 更新期望 $O(\log N)$ 个祖先；
- 一次 `add/del` 只进行常数次路径操作与采样信息更新；
- `map` 查边的代价为 $O(\log N)$。

所以，一次加删边的常规维护期望为

$$
O(RL\log N).
$$

一次 `find_crossing` 尝试至多 $RL$ 个采样候选。每个候选通过父指针寻找所属根，需要期望 $O(\log N)$，因此不计兜底扫描时，它也是

$$
O(RL\log N).
$$

最近连接缓存只有固定的 $64$ 项，不改变这个渐进界。一次 `splice` 同样是常数次 Treap 操作。

### 13.2 全部查询中的拼接次数总共只有 O(q)

设根列表当前有 $c$ 条路径或回路：

- 一次加边先创建一条单边路径，所以使 $c$ 增加至多 $1$；之后配对只会合并或闭合路径；
- 一次删边把一条路径切成至多两条，所以使 $c$ 增加至多 $1$；之后配对也不会增加路径数；
- 一次查询中的 `splice` 使 $c$ 减少 $1$。

开始时 $c=0$，且 $c$ 始终非负。因此全部查询中的 `splice` 总数不超过加删边操作数，为 $O(q)$。

注意这里统计的是所有查询加起来的拼接次数，不是说每次 `query` 都只拼接常数次。

### 13.3 把扫描开销单独列出来

令 $W$ 表示所有兜底扫描实际花费的总工作量。初始化为 $O((n+q)RL)$，`query_path` 最多调用 $10$ 次，输出总代价为 $O(q)$。

在上述 Treap 假设下，完整的期望时间应写成

$$
O\bigl((n+q)RL+qRL\log N+\mathbb E[W]\bigr).
$$

不能遗漏 $\mathbb E[W]$。

因为单次扫描为 $O(m)\subseteq O(q)$，而查找次数总共为 $O(q)$，扫描部分有确定的上界

$$
W=O(q^2).
$$

这只给出了一个保守上界，并没有证明当前实现的扫描期望一定很小。

主要空间来自 `value,sum,vertex_sum`，按所支持的规模上限计为

$$
O((n+q)RL).
$$

其余结点、半边、父指针、邻接表、映射和临时数组不会超过这个量级。当前 C 数组版按照统一上限预留容量；空间估计应以预留上限为准。

## 14. O(N log³ N) 具体基于什么假设

这个估计需要同时满足下面三个条件。

### 条件一：Treap 操作适用标准的期望对数复杂度

需要能够对实际发生的操作使用

$$
\mathbb E[\text{经过的 Treap 结点数}]=O(\log N)
$$

的分析。通常将优先级视为足够独立的随机数，并要求序列与操作的选择满足标准随机 Treap 分析的前提，而不能根据优先级主动挑选坏形状。

这解释了第一个 $\log N$。

### 条件二：按对数级采样规模进行理论计数

理论估算中令

$$
L=\Theta(\log N),\qquad R=\Theta(\log N).
$$

每个 Treap 结点维护 $RL=O(\log^2N)$ 个采样量，一次路径操作经过期望 $O(\log N)$ 个结点，于是常规维护总计

$$
O(N\log^3N).
$$

三个对数分别来自：Treap 操作、采样层数、独立采样组数。

这里是在解释复杂度式子的组成，并不是给当前代码的固定参数 `groups=3,levels=20` 自动赋予同样的概率保证。

### 条件三：实际产生的分割具有足够小的扫描概率

这是当前分析中尚未证明的关键条件。

设第 $t$ 次调用 `find_crossing` 时，$F_t$ 表示最终需要进入精确扫描。一个足够使用的假设是：对每一次实际查找，都有

$$
\Pr(F_t)\le \frac{C}{N},
$$

其中 $C$ 为与规模无关的常数。不存在的查找编号可以视为不发生扫描，这样查找总次数有统一的 $O(q)$ 上限。

每次扫描最多花费 $O(q)$，所以由期望的线性性，

$$
\mathbb E[W]
\le
\sum_{t=1}^{O(q)}O(q)\Pr(F_t)
=
O\left(\frac{q^2}{N}\right)
=
O(N).
$$

于是扫描开销不会超过常规维护开销，才能得到整体期望

$$
O(N\log^3N).
$$

更强、也足够使用的版本是：给定此前用于决定回路结构的决策历史 $\mathcal H_t$，仍有

$$
\Pr(F_t\mid\mathcal H_t)\le \frac{C}{N}.
$$

但这不是唯一可能的证明方式。直接证明所有扫描的总期望足够小，也可以达到目的。

**不同次扫描事件不需要互相独立。** 上面的求和只使用期望线性性；需要的是每个实际事件的概率界，或者一个有效的全局摊还分析。

### 为什么固定分割的概率分析还不够

对一个预先固定、与采样随机数独立的分割 $S$，几何采样可以给出每组的常数成功概率；独立重复后，可以把失败概率压低到所需量级。

问题在于，当前程序会用采样结果决定 `splice` 的连接位置。后续回路结构、删边后产生的路径，以及下一次查找的分割，都可能依赖之前的采样结果。另一方面，同一个存活半边的采样高度始终复用。

若把全部采样随机数写成 $\omega$，已知的是

$$
\forall\text{固定 }S,\quad
\Pr_\omega[\text{采样在 }S\text{ 上失败}]\le\varepsilon.
$$

当前程序实际需要处理的却是

$$
S_t=S_t(\omega).
$$

前一个式子不能自动推出

$$
\Pr_\omega[\text{采样在 }S_t(\omega)\text{ 上失败}]
\le\varepsilon.
$$

即使外部加删边序列事先固定、完全不知道随机种子，程序内部的分割仍然可能依赖随机结果。

因此，这份题解可以给出完整的答案正确性证明，也可以算清常规维护开销，但尚未给当前实现补齐上述第三个条件。**$O(N\log^3N)$ 应标注为基于这些假设的估算，不能写成这份程序已经证明的全局期望复杂度。**

关于这个独立性要求，可参考 Zhengyu Wang 的 [An Improved Randomized Data Structure for Dynamic Graph Connectivity](https://arxiv.org/html/1510.04590v1) 中的 Lemma 1 及其后的讨论：cutset 结构不能直接用自己的随机输出改变它维护的森林后，继续套用原来的概率保证；文中通过分层结构处理这一问题。

## 15. 完整代码

下面附上本文对应的 C 数组版代码。函数名与前文一一对应，保留当前参数，不包含小点数 bitset 分支、位打包或祖先缓存。


```cpp
#include"path.h"
#include<bits/stdc++.h>
using namespace std;

namespace Euler{
using ll=long long;
const int N=200005,mod=998244353,groups=3,levels=20;
mt19937 rng;

// 一条边 e 对应一个 Treap 结点，两个半边的编号为 2e、2e+1。
// ver[p] 是半边所在的顶点，mate[p] 是同一顶点处与它配对的半边。
// 沿着 p -> mate[p^1] 前进，就能走出维护的路径或回路。
// 每个点最多保留一个未配对半边 unmatched[v]，故查询时只剩回路。
// p 是当前边的出发半边，first、last 是整段路径两端的半边。
// h、rh 分别记录正向、反向行走时每条边起点的哈希。
struct Node{
	int l=0,r=0,fa=0,sz=0,p=0,first=0,last=0,h=0,rh=0;
	unsigned pri=0;
	bool rev=false;
};
struct Sketch{
	int a[groups][levels]={};
	void operator^=(const Sketch &b){
		for(int j=0;j<groups;j++)for(int i=0;i<levels;i++)a[j][i]^=b.a[j][i];
	}
};
Node t[N];
Sketch value[N],sum[N],vertex_sum[N];
int height[N*2][groups];
vector<int>adj[N];
int ver[N*2],mate[N*2],pos[N*2],unmatched[N],pw[N];
int roots[N],where[N],mark[N],nodes[N],recent[64];
map<pair<int,int>,int>edge_id;
int tot,stamp,root_count,recent_count;

pair<int,int>key(int u,int v){return {min(u,v),max(u,v)};}
int representative(int v){return adj[v].empty()?0:adj[v][0];}
int getroot(int x){while(t[x].fa)x=t[x].fa;return x;}

// 第 i 层以约 2^(-i) 的概率保留一个半边编号，三组各自采样。
// height 在半边创建时生成，此后重复异或同一个编号就能撤销它。
void toggle(Sketch &s,int p){
	for(int j=0;j<groups;j++)for(int i=0;i<=height[p][j];i++)s.a[j][i]^=p;
}
void pull_sum(int x){
	int l=t[x].l,r=t[x].r;
	for(int j=0;j<groups;j++)for(int i=0;i<levels;i++)
		sum[x].a[j][i]=sum[l].a[j][i]^sum[r].a[j][i]^value[x].a[j][i];
}
void pull(int x){
	int l=t[x].l,r=t[x].r;
	t[x].sz=t[l].sz+t[r].sz+1;
	t[x].first=l?t[l].first:t[x].p;
	t[x].last=r?t[r].last:(t[x].p^1);
	t[x].h=(t[l].h+(ll)ver[t[x].p]*pw[t[l].sz]+(ll)t[r].h*pw[t[l].sz+1])%mod;
	t[x].rh=(t[r].rh+(ll)ver[t[x].p^1]*pw[t[r].sz]+(ll)t[l].rh*pw[t[r].sz+1])%mod;
	pull_sum(x);
	if(l)t[l].fa=x;
	if(r)t[r].fa=x;
}
void reverse(int x){
	if(!x)return;
	swap(t[x].l,t[x].r);swap(t[x].first,t[x].last);swap(t[x].h,t[x].rh);
	t[x].p^=1;t[x].rev^=1;
}
void push(int x){
	if(t[x].rev){reverse(t[x].l);reverse(t[x].r);t[x].rev=false;}
}
int merge(int x,int y){
	if(!x||!y){int r=x+y;if(r)t[r].fa=0;return r;}
	if(t[x].pri<t[y].pri){
		push(x);t[x].r=merge(t[x].r,y);pull(x);t[x].fa=0;return x;
	}
	push(y);t[y].l=merge(x,t[y].l);pull(y);t[y].fa=0;return y;
}
// 常规 FHQ split：前 k 条边归 a，其余归 b。
void split(int x,int k,int &a,int &b){
	if(!x){a=b=0;return;}
	push(x);
	if(t[t[x].l].sz>=k){b=x;split(t[x].l,k,a,t[x].l);pull(b);}
	else{a=x;split(t[x].r,k-t[t[x].l].sz-1,t[x].r,b);pull(a);}
	if(a)t[a].fa=0;
	if(b)t[b].fa=0;
}
void push_path(int x){
	if(t[x].fa)push_path(t[x].fa);
	push(x);
}
int getrank(int x){
	push_path(x);
	int k=t[t[x].l].sz+1;
	while(t[x].fa){
		int f=t[x].fa;
		if(t[f].r==x)k+=t[t[f].l].sz+1;
		x=f;
	}
	return k;
}
// 采样异或与顺序无关，更新它时不必下传翻转标记。
void refresh(int x){for(;x;x=t[x].fa)pull_sum(x);}
void insert_root(int x){if(x){where[x]=root_count;roots[root_count++]=x;}}
void erase_root(int x){
	int i=where[x],y=roots[--root_count];roots[i]=y;where[y]=i;
}

// 两个裸露半边在同一顶点处接起来：不同路径合并，同一路径闭合。
void join(int p,int q){
	int x=getroot(p>>1),y=getroot(q>>1);
	mate[p]=q;mate[q]=p;
	if(x==y)return;
	erase_root(x);erase_root(y);
	if(t[x].last!=p)reverse(x);
	if(t[y].first!=q)reverse(y);
	insert_root(merge(x,y));
}
void expose(int p){
	if(!p)return;
	int v=ver[p],q=unmatched[v];
	if(q){unmatched[v]=0;join(p,q);}
	else unmatched[v]=p;
}

// 寻找公共顶点用的辅助图：每个半边 p 连接到该顶点的代表半边 h。
// 将编号 p 分别异或到 p、h 所属的边结点上，内部辅助边就会抵消。
// vertex_sum[v] 汇总 v 的全部半边，代表被删时可整体交给新代表。
void attach(int p){
	int v=ver[p],h=representative(v);
	if(!h)h=p;
	pos[p]=adj[v].size();adj[v].push_back(p);
	toggle(vertex_sum[v],p);toggle(value[p>>1],p);toggle(value[h>>1],p);
	refresh(h>>1);
}
void detach(int p){
	int v=ver[p],h=representative(v),last=adj[v].back();
	// 用末尾元素填补空位，O(1) 删除邻接表中的半边。
	adj[v][pos[p]]=last;pos[last]=pos[p];adj[v].pop_back();
	toggle(vertex_sum[v],p);
	if(h!=p){toggle(value[h>>1],p);refresh(h>>1);}
	else if((h=representative(v))){value[h>>1]^=vertex_sum[v];refresh(h>>1);}
}

// 将闭合回路反向、旋转，使其从半边 p 出发。
int rotate(int p){
	int x=p>>1,r=getroot(x),k=getrank(x),a,b;
	if(t[x].p!=p){reverse(r);k=t[r].sz-k+1;}
	split(r,k-1,a,b);
	return merge(b,a);
}
void splice(int p,int q){
	int a=mate[p],b=mate[q];
	erase_root(getroot(p>>1));erase_root(getroot(q>>1));
	int x=rotate(p),y=rotate(q);
	mate[p]=b;mate[b]=p;mate[q]=a;mate[a]=q;
	insert_root(merge(x,y));
}
bool crossing(int p,int r){
	if(p<2||p>2*tot+1||!ver[p])return false;
	int x=getroot(p>>1),y=getroot(representative(ver[p])>>1);
	return x!=y&&(x==r||y==r);
}
int remember(int p){
	recent[recent_count++%64]=p;return p;
}
int find_crossing(int r){
	for(int i=levels-1;i>=0;i--)for(int j=0;j<groups;j++){
		int p=sum[r].a[j][i];
		if(crossing(p,r))return p;
	}
	// 保留最近找到的连接，避免相同分割反复触发扫描。
	for(int i=max(0,recent_count-64);i<recent_count;i++){
		int p=recent[i%64];
		if(crossing(p,r))return p;
	}
	// 采样失败则精确扫描。随机性只影响时间，不影响答案正确性。
	++stamp;int cnt=1;nodes[0]=r;
	for(int i=0;i<cnt;i++){
		int x=nodes[i];mark[x]=stamp;
		if(t[x].l)nodes[cnt++]=t[x].l;
		if(t[x].r)nodes[cnt++]=t[x].r;
	}
	for(int i=0;i<cnt;i++)for(int p=nodes[i]*2;p<=nodes[i]*2+1;p++){
		int v=ver[p],h=representative(v);
		if(mark[h>>1]!=stamp)return remember(p);
		if(p==h)for(int q:adj[v])if(mark[q>>1]!=stamp)return remember(q);
	}
	assert(false);return 0;
}
}

void init(int n,int q){
	using namespace Euler;
	tot=stamp=root_count=recent_count=0;
	rng.seed(chrono::steady_clock::now().time_since_epoch().count());
	fill(t,t+q+1,Node());fill(value,value+q+1,Sketch());fill(sum,sum+q+1,Sketch());
	fill(ver,ver+2*q+2,0);fill(mate,mate+2*q+2,0);fill(mark,mark+q+1,0);
	for(int i=0;i<=n;i++){vertex_sum[i]=Sketch();unmatched[i]=0;adj[i].clear();}
	pw[0]=1;
	for(int i=1;i<=q+1;i++)pw[i]=(ll)pw[i-1]*100%mod;
	edge_id.clear();
}
void add(int u,int v){
	using namespace Euler;
	int x=++tot,p=x*2;edge_id[key(u,v)]=x;
	ver[p]=u;ver[p+1]=v;t[x].p=p;t[x].pri=rng();
	for(int s=p;s<=p+1;s++)for(int j=0;j<groups;j++){
		int h=0;
		while(h+1<levels&&!(rng()&1))h++;
		height[s][j]=h;
	}
	attach(p);attach(p+1);pull(x);insert_root(x);
	expose(p);expose(p+1);
}
void del(int u,int v){
	using namespace Euler;
	auto it=edge_id.find(key(u,v));int x=it->second;edge_id.erase(it);
	int p=x*2,a=mate[p],b=mate[p+1],r=getroot(x),k=getrank(x),left,right;
	bool closed=mate[t[r].first]==t[r].last;
	erase_root(r);
	split(r,k-1,left,right);split(right,1,x,right);
	// 闭合回路 A,e,B 删除 e 后成为 B,A；开放路径则拆成 A 和 B。
	if(closed)insert_root(merge(right,left));
	else{insert_root(left);insert_root(right);}
	if(a)mate[a]=0;else unmatched[ver[p]]=0;
	if(b)mate[b]=0;else unmatched[ver[p+1]]=0;
	mate[p]=mate[p+1]=0;
	detach(p);detach(p+1);
	expose(a);expose(b);ver[p]=ver[p+1]=0;
}
int query(){
	using namespace Euler;
	// 查询时所有点度数为偶数，所有路径都已闭合，只需拼接各个回路。
	while(root_count>1){
		int r=roots[root_count-1],s=roots[root_count-2];
		if(t[s].sz<t[r].sz)r=s;
		int p=find_crossing(r);splice(p,representative(ver[p]));
	}
	int r=roots[0];
	// h 只存每条边的起点，还需补上最后一个顶点。
	return (t[r].h+(ll)ver[t[r].last]*pw[t[r].sz])%mod;
}
vector<int> query_path(){
	using namespace Euler;
	int r=roots[0],p=t[r].first;
	vector<int>ans(t[r].sz+1);
	for(int &v:ans){v=ver[p];p=mate[p^1];}
	return ans;
}
```
