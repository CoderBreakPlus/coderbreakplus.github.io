首先操作相当于把序列划分成若干段，每一段里面 xor 上任意一个数，最后整个序列要递增。

考虑每一个段 $[l,r]$ 存在一个 $x$，使得 $a_i \oplus x$ 递增的判定：$a_i \oplus x \le a_{i+1} \oplus x$ 当且仅当 $x$ 的二进制下第 $\text{highbit}(a_i \oplus a_{i+1})$ 位和 $a_i$ 相同。

据此可以写出一个显然的贪心，但是问题在于最后一段有可能 $x$ 可以是 $0$，这样答案就能少 $1$。

考虑 DP 来检查答案能不能少 $1$：令 $f_i$ 表示 $[1,i]$ 的最少划分段数，$dp_i$ 表示在 $[1,i]$ 中，划分段数量最少的情况下，最小的操作后的 $a_i$。

转移的时候考虑将所有 $f_i = x$ 的点的 $dp$ 转移到 $f_i = x+1$ 的。

用一棵 01-trie 来维护所有合法的 $x$。具体的：

+ 加入 $dp_i$ 时，所有 $dp_i \le a_{i+1} \oplus x$ 的 $x$ 都变得可行；
+ 加入 $a_i \oplus x \le a_{i+1} \oplus x$ 的限制时，会要求 $x$ 的二进制下某一位具体是多少。
+ 算 $dp_i$ 的时候查询 $\min \limits_x (a_i \oplus x)$。

第三种操作就是 01-trie 上从上到下走一遍。

首先如果第二种操作不会出现矛盾的限制的话（就是既限制第 $k$ 位是 $0$，又限制第 $k$ 位是 $1$），那么 01-trie 的任意一个高于第 $k$ 位的子树是不会被删除的。

> 注意矛盾的限制并不意味着 trie 树被删空，因为有可能先加入限制再加入一个 $dp_i$。

于是可以直接暴力维护 01-trie，每次第二种操作时，直接把这一层的不合法点全都删掉，并顺便向上 pushup（如果父结点的子树被删空了，父结点也删掉，递归上去）。

但是这样递归到一个满的子树的时候（整个子树的 $x$ 都被加入，显然在第一种操作时只在这里打了 tag，它是没有后代的），并不意味着这里面的 $x$ 都合法，因为会有一些对更低位的限制。

因此我们要记录这个 01-trie 上每个结点子树内最晚加入的 $dp_i$，因为越晚加入，对它的限制就越松。

那么记录了时间戳以后有矛盾的限制也不怕了，直接处理出来以当前的 $i$ 结尾，向左最长延伸到哪里，在 01-trie 上走的时候也要看一下最大时间戳能否满足要求。

这样查询就不均摊了，修改是均摊的，比题解区查询均摊，修改不均摊的做法难写多了，不建议学习。
